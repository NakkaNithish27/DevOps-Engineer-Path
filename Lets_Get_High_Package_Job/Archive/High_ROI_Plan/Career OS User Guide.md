# CAREER OS USER GUIDE

Version: 2.0

Purpose:

This document explains how to use the Career Operating System.

It is written for the user.

It is **not** part of the Career Operating System itself.

Instead, it explains how to interact with JARVIS and how the Career Operating System works behind the scenes.

The objective is to make using the system effortless while allowing JARVIS to manage the complexity.

---

# THE PHILOSOPHY

The Career Operating System exists for one purpose:

**To maximize career growth while minimizing maintenance.**

My responsibility is to:

* Learn
* Build
* Debug
* Practice
* Ask questions

JARVIS is responsible for everything else.

Whenever there is a choice between:

Maintaining the Career OS

or

Building engineering skill

Always choose engineering.

---

# CAREER OS ARCHITECTURE

The Career Operating System consists of eight specialized documents.

Each document has exactly one responsibility.

```text
                    YOU
                     │
                     ▼
                 JARVIS
        (Career Session Interface)
                     │
     ┌───────────────┼────────────────┐
     │               │                │
     ▼               ▼                ▼
Career OS     Active Workspace   Reference Documents
(Constitution)  (Working Memory)     (Long-Term Memory)
                     │
                     ▼
             Engineering Work
                     │
                     ▼
              End Session
                     │
                     ▼
     Updated Active Workspace Only
```

The architecture is intentionally designed so that:

* I interact with **JARVIS**
* JARVIS interacts with the Career OS
* I normally update only **one document**

---

# DOCUMENT RESPONSIBILITIES

## 1. JARVIS

The interface.

This is the entry point to every session.

Responsibilities:

* Initialize sessions
* Load the minimum required documents
* Guide learning
* Track progress
* Preserve context
* Update the Active Workspace
* Recommend Evolution Sessions

---

## 2. Career Operating System

The constitution.

Defines:

* Philosophy
* Principles
* Constraints
* Long-term optimization goals

Rarely changes.

---

## 3. Career Execution Roadmap

The strategy.

Defines:

* Career direction
* Milestones
* Long-term execution strategy

Rarely changes.

---

## 4. Active Workspace

Working memory.

This is the only document normally updated.

It contains:

* Current priorities
* Current projects
* Session history
* Blockers
* Outputs
* Knowledge candidates
* Opportunity candidates
* Roadmap observations
* System improvement ideas

---

## 5. Career Pipeline

Career database.

Stores long-term career information.

Examples:

* Applications
* Recruiters
* Interviews
* Resume evolution
* LinkedIn evolution
* Market observations
* Offers

Updated only during Evolution Sessions or major career events.

---

## 6. Engineering Knowledge Base

Engineering database.

Stores timeless engineering knowledge.

Examples:

* Troubleshooting playbooks
* Architecture patterns
* Engineering principles
* Best practices
* Interview knowledge
* Decision frameworks

Updated only during Evolution Sessions.

---

## 7. Career Decision Engine

Decision framework.

Determines the highest-leverage action whenever priorities are unclear.

It optimizes for Career ROI rather than technical curiosity.

---

## 8. Career System Review

Architecture review.

Improves the Career Operating System itself.

Used rarely.

# EVOLUTION WORKFLOW

Evolution Sessions are intentionally rare.

They exist to synchronize long-term knowledge.

```text
Many Productive Sessions

        │

        ▼

Active Workspace
Accumulates Knowledge

        │

        ▼

JARVIS Recommends
Evolution Session

        │

        ▼

Upload Required
Reference Documents

        │

        ▼

Synchronize

• Engineering Knowledge Base
• Career Pipeline
• Career Roadmap
• Career Operating System
• Career Decision Engine
• JARVIS (if needed)

        │

        ▼

Archive Current Workspace

        │

        ▼

Create Fresh Active Workspace

        │

        ▼

Continue Engineering Work
```

Evolution Sessions should occur only when meaningful changes have accumulated.

Never perform them simply because a certain amount of time has passed.

# WHAT SHOULD I MAINTAIN?

During normal work:

Only one document.

**Active Workspace**

Everything else is maintained only during Evolution Sessions.

This is the most important design principle of the Career Operating System.

---

# WHAT SHOULD A SUCCESSFUL SESSION PRODUCE?

Every productive session should create measurable career value.

Examples:

* Working code
* Production-quality project
* GitHub improvement
* Better documentation
* Architecture diagram
* Troubleshooting experience
* Automation
* Interview preparation
* Better engineering understanding

Hours spent are irrelevant.

Outputs produced are what matter.

---

# WHAT SHOULD I AVOID?

Avoid:

* Endless tutorials
* Passive learning
* Collecting notes
* Maintaining multiple documents
* Updating reference documents after every session
* Overengineering the Career Operating System
* Optimizing the system instead of improving engineering ability

Remember:

The Career Operating System exists to support engineering.

Engineering does not exist to support the Career Operating System.

---

# HOW TO MEASURE SUCCESS

Do not measure:

* Hours studied
* Courses completed
* Notes written

Instead measure:

* Production-quality projects
* Engineering confidence
* Troubleshooting ability
* GitHub quality
* Interview confidence
* Recruiter interest
* Career opportunities
* Market value
* Career leverage

The objective is not to become busy.

The objective is to become employable.

---

# THE FEEDBACK LOOP

The Career Operating System is designed to continuously improve while reducing maintenance.

```text
Engineering Work

        │

        ▼

Active Workspace

        │

        ▼

JARVIS

        │

        ▼

Evolution Session (Rare)

        │

        ▼

Reference Documents

        │

        ▼

Better Decisions

        │

        ▼

Better Engineering Work

        │

        ▼

Repeat
```

Every cycle should increase career value while making the system simpler to use.

---

# GOLDEN RULES

1. Start every session with JARVIS.

2. Let JARVIS decide which documents are needed.

3. Focus on building, not maintaining the system.

4. Update only the Active Workspace after normal sessions.

5. Trust JARVIS to preserve context.

6. Perform Evolution Sessions only when meaningful improvements have accumulated.

7. Prefer simple systems over complicated ones.

8. Every engineering session should leave behind measurable career value.

---

# FINAL PRINCIPLE

The highest achievement of this Career Operating System is not perfect organization.

It is becoming almost invisible.

I should spend nearly all of my time:

* Building
* Learning
* Debugging
* Creating
* Solving engineering problems

JARVIS should quietly remember everything else.

If I rarely think about maintaining the Career Operating System, yet continuously become a stronger engineer, then the system is functioning exactly as intended.
